# Stage 3 — Existing Tools, Precedents, and No-Build Alternatives

**Status:** Not started
**Phase:** Research only

Read the completed Stages 0–2 record and research/stages/stage-03-competitors.md completely.

## Objective

Find the cheapest existing way to produce the intended outcome before choosing custom software.

## Compare

1. Spreadsheet or shared-table workflow.
2. Existing experiment or evaluation trackers.
3. Model-provider histories, usage exports, or project records.
4. Media review and comparison tools.
5. Native browser capabilities.
6. The working Creative Run Review.
7. The release checker and other preserved alternatives.
8. No-build.

## Method

- Inspect only tools that cover a distinct part of the intended workflow.
- Use official documentation for capabilities and access models.
- Do not make a generic tool roundup or compare headline prices as equivalent.
- Record adoption burden, data handling, exportability, vendor lock-in, and what remains Unknown.
- Apply the internship matrix: HexCoded relevance, founder/demo value, feasibility, technical learning, no privileged access, evidence honesty, and reversibility.

## Required output

Add a 3–5 direction comparison, the simplest sufficient alternative, a provisional winner, discarded scope, and reopening conditions to implementation/cumulative-report.md. Update implementation/handoff.md.

Do not write application code or install dependencies.

## Exit gate

If a spreadsheet or existing tool creates the same useful and demonstrable outcome, select it or define the one narrow capability it lacks. Do not build around an invented gap.
